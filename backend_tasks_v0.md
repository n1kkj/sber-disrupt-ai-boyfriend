# Backend Tasks V0

## Цель MVP

Дать пользователю единого AI-companion в Telegram и на сайте: общий аккаунт,
общая история, текстовые и голосовые сообщения, базовая память и первые
проактивные сообщения. Продукт должен поддерживать как AI-boyfriend, так и
AI-girlfriend.

Главный принцип: сначала надежный единый message-flow, затем мультимодальность,
память и сложная проактивность.

## Базовый стек

- **API:** FastAPI, async SQLAlchemy, Alembic.
- **Основная БД:** PostgreSQL.
- **Очереди и расписание:** Celery + Redis broker/result backend.
- **Отмена и состояние фоновых задач:** Redis с TTL.
- **Файлы:** S3-compatible storage, локально MinIO.
- **AI:** Gemini через OpenAI-compatible API и текущий `GeminiAIService`.
- **Векторный поиск:** pgvector в PostgreSQL. На первом этапе достаточно top-k
  поиска по последним сообщениям и небольшому числу memory chunks.
- **Telegram:** webhook и polling через переключатель в env.
- **Наблюдаемость:** структурированные логи, Sentry/OpenTelemetry позже.

## Архитектурные правила

- Поток: `view -> service -> dao -> database`.
- Роутеры находятся в `app/views`.
- ORM-код находится только в DAO.
- Один SQLAlchemy model и одна DTO-схема на файл.
- Методы DAO и сервисов делают classmethod; зависимости не создаются в каждом
  запросе.
- Фоновые операции запускаются через Celery tasks, а не выполняются внутри
  HTTP-запроса или Telegram update handler.
- Входящие сообщения должны иметь `external_id` и `idempotency_key`, чтобы
  повторная доставка Telegram/webhook не создавала дубли.
- Все компоненты используют единый `app/logging.py`: логируют начало,
  успешное завершение и ошибку операции в консоль и rotating-файл; секреты,
  пароли и полный текст сообщений в лог не попадают.

### 2.2. Фоновая обработка сообщений

  загрузить сообщение, собрать контекст, вызвать Gemini, сохранить ответ.
- [x] Task должна быть идемпотентной: повторный запуск не создает второй ответ.

### 2.3. Отложенные сообщения и отмена

- [x] Создать Redis-ключ задачи вида `scheduled_message:{task_id}` с TTL.
- [x] В значении хранить `task_id`, `user_id`, `chat_id`, тип сообщения,
  время отправки и статус.
- [x] Для отложенной отправки использовать `apply_async(eta=...)` или countdown.
- [x] Реализовать `cancel_scheduled_message(task_id)` через
  `celery.control.revoke(task_id)` и обновление статуса в Redis.
- [x] Перед отправкой task повторно проверяет статус отмены в Redis.
- [x] Добавить API для создания, просмотра и отмены отложенных сообщений.
- [x] Учитывать часовой пояс пользователя и quiet hours.

**Готово, когда:** запланированное сообщение можно увидеть, отменить до
отправки, а повторный запуск worker не отправляет его дважды.

> Важно: `revoke` не является единственной защитой. Проверка статуса в Redis
> непосредственно перед отправкой обязательна, потому что задача могла уже
> попасть в worker.

## Минимальный порядок реализации

1. `Message` + `MediaAsset` + идемпотентность.
2. Celery + Redis + `process_message`.
3. Общая история и доставка ответа на сайт/в Telegram.
4. Отложенные сообщения, Redis-статусы и отмена.
5. Onboarding, роли пользователя/companion и `CharacterVersion`.
6. Голосовой ввод.
7. Базовая memory extraction и pgvector top-k.
8. Изображения, реакции и аналитика.
9. TTS и проактивные сообщения.
10. Видео, privacy hardening и production observability.

## Definition of Done для V0

- Пользователь сайта и Telegram связан одним аккаунтом.
- Текстовое сообщение проходит через Celery и возвращает ответ в исходный канал.
- История общая для сайта и Telegram.
- Отложенное сообщение можно создать, увидеть и отменить.
- Повторная доставка update не создает дублей.
- Gemini временно недоступен без потери сообщения: задача повторяется или
  получает понятный failed-статус.
- Голос расшифровывается и обрабатывается как обычное сообщение.
- Пользователь может выбрать AI-boyfriend или AI-girlfriend, а настройки роли,
  гендера и обращений одинаково работают на сайте и в Telegram.
- Бот помнит только несколько подтвержденных фактов через простую memory/RAG
  схему.
- Все настройки очередей, Redis, Telegram и Gemini задаются через nested
  settings и `.env`.
